# Multi-bandwidth forward proposals at genuine fine control levels

## Predeclared research card

**Question.** The current sparse-match forward decoder updates 17², 33² and 65², then only subdivides to 257². Can scale-dependent proposals at 129² and 257² create genuine fine-level detail while preserving the same fixed-table homeomorphism guarantee and a useful forward/VJP cost?

**Exact construction.** Given matches \(q_i\mapsto p_i\), define \(d_i=p_i-q_i\) and \(D_\sigma(v)=\sum_i\exp(-\|v-q_i\|^2/(2\sigma^2))d_i/[\sum_i\exp(-\|v-q_i\|^2/(2\sigma^2))+10^{-8}]\). At grid sizes \(n_l=17,33,65,129,257\), choose in advance \(\sigma_l=(.12,.06,.03,.015,.01)\) in unit-square coordinates and propose \(v+D_{\sigma_l}(v)\) to the existing four-color F1-D safety layer, with each level refining the previous map exactly before moving vertices. Each F1-D update protects all four Q1 corner determinants; no inverse solve or post-hoc fold repair occurs. The output can be interpreted either with Q1 interpolation or with the declared fixed SW–NE P1 triangulation, with separate accuracy evaluation.

**Assumptions.** Initially identity boundary, finite matches in the unit square, positive widths, F1's established exact-arithmetic corner-safety hypotheses, and output-side positive affine if used. Finite-precision output still needs a saved-binary audit. Gaussian interpolation by itself is not injective. The two finest levels move only if their target proposal differs from the refined previous map; hence unlike pure subdivision they can introduce new P1/Q1 detail.

**What would falsify utility.** Failure to reduce 257² vertex error on a valid high-frequency target versus the frozen coarse-only schedule; unacceptably large forward/VJP time or memory; nonpositive saved corner signs; nonfinite match-coordinate VJP. Improvement on a synthetic target would establish expressivity of one input class, not image-to-latent generalization.

**Smallest decisive test.** Use \(T_a(x,y)=(x+a\sin(8\pi x)\sin(8\pi y),y)\), \(a=.02\), and 16×16 match centers \(((i+1/2)/16,(j+1/2)/16)\). Its continuum determinant is at least \(1-8\pi a>0\), and check sampled Q1 signs as an independent prerequisite. Compare coarse-only fixed \(\sigma=.12\) update levels through 65² against the five-level schedule above on the same 257² target, with no fitting. Report full-grid vertex RMSE, held-out off-grid query error, saved-binary Q1/P1 signs, input-match VJP, and GPU forward/VJP/peak allocated memory. If successful, test the same predeclared widths on the three sparse real-match development pairs without tuning to anatomy. Do not call those development results independent validation.

**Prior work / novelty boundary.** Gaussian interpolation and multiscale motion are established tools; the claim under test is their concrete interaction with the hard F1-D safety update at genuine dense control levels. The construction is a proposal decoder, not proof of universal approximation or a learned image frontend.

The two saved candidate maps also had exact-binary positive Q1 signs in all 262,144 corners and identity boundaries. Errors are vector root-mean-square in unit-square coordinates. **Follow-up question.** Can the same Gaussian sum and its match-coordinate VJP be computed with much lower memory, without changing the proposal or safety theorem? On a tensor-product grid \(x_j,y_i\), write \(X_{jm}=\exp[-(x_j-q_{m,x})^2/(2\sigma^2)]\), \(Y_{im}=\exp[-(y_i-q_{m,y})^2/(2\sigma^2)]\). Then \(w_{ijm}=Y_{im}X_{jm}\), denominator \(YX^T\), and numerator for displacement component \(c\) equals \([Y\operatorname{diag}(d_{:,c})]X^T\). Three matrix products therefore evaluate the *same finite sum* with \(O((H+W)M+HW)\) stored scalars instead of \(O(HWM)\). The identities are exact over the reals; floating-point summation order can change the last bits and thus requires a new saved certificate. Test direct-versus-separable outputs and source/target VJP on small double-precision grids, then rerun the frozen 257² comparison on the same hardware and report both speed and allocated memory. A faster matrix product is an engineering improvement, not new mathematics.

The direct/separable double-precision unit fixture agrees in values to `1e-14` absolute and in source/target VJPs to `1e-12` absolute. On the same A6000 GPU0 and otherwise identical synthetic protocol, the separable implementation returned the **same six-decimal vertex and off-grid errors** as above, with a tiny floating-order difference between saved float32 maps: maximum vertex-coordinate differences `1.79e-7` for coarse-only and `5.96e-8` for five-level. Both newly saved maps independently passed exact-binary Q1 corner checks, and every match-coordinate VJP was finite. The implementation calls the Gaussian routine only on the regular reference grid; applying this factorization to a warped/non-tensor grid would be invalid.

Forward allocated peak falls from 411.6 to 38.7 MB (about 10.6-fold) and measured forward time changes from 17.90 to 16.77 ms. These are single-device short-run engineering measurements, not multi-pair speed distributions; peak measurement includes some post-timing diagnostics. The memory reduction does not eliminate O(HW) map storage, nor does it make the external image matcher/affine initializer cheap. ## Independent separable-kernel review

The matrix identity is correct **on a tensor-product reference grid**: the Gaussian exponent splits into x/y terms, so mass is `Y Xᵀ` and component numerator is `(Y*d_c) Xᵀ`. This retains the same stabilizer `+1e-8`; it changes storage and floating-point evaluation order, not the real-valued finite sum. Gaussian arithmetic remains O(HWM); the improvement is O((H+W)M+HW) intermediate storage, plus the existing safety layer. An independent rectangular 11×17 NumPy calculation agrees with the new routine within `6.94e-18`; a source/target directional derivative agrees with central differences within `8.26e-11`.

All four saved archives independently have **262,144 strictly positive arbitrary-precision integer Q1 corner signs**, exact identity boundaries and identity affine factors. Minimum normalized exact determinants are **.87750244140625** for both coarse maps and **.049999237060546875** for both fine maps. Thus the saved Q1/P1 interpretations are valid, but an exact stored .05 floor is slightly missed. Direct and separable maps are **not bitwise identical**: 618/1,591 coordinate components differ for coarse/fine, with maxima **1.7881393e-7 / 5.9604645e-8**.

Recomputing against the analytic target in float64 and using direct four-weight Q1 interpolation on the same 10,000 seeded queries gives direct coarse/fine vertex RMSE **.009924514525/.005072964943** and off-grid RMSE **.010017323550/.005019971380**. Separable values are **.009924514482/.005072964693** and **.010017323509/.005019971155**. These support the reported errors within `1e-9`, without calling the experiment evaluator. The continuum determinant lower bound is valid; sampling this particular sine shear also preserves positive Q1 x-derivatives by the mean-value theorem, unlike an arbitrary sampled diffeomorphism.

Two boundary attacks were decisive. Perturbing one interior grid coordinate breaks separability and produced **.003035** discrepancy from the direct formula; current callers correctly pass the undeformed reference grid. A positive but tiny float32 width `1e-30` formerly passed validation and produced **58 NaN components** through denominator underflow. The author added a dtype-aware width floor and float32/float64 restriction; independent retesting confirms rejection of that input and finite values/gradients at each dtype's `sqrt(finfo.tiny)` boundary. Updated tests: **9 passed, 1 CUDA-only test skipped**. Empty, zero and NaN width schedules are rejected.

The reports support fine-level allocated-peak reductions of **10.632× forward / 6.409× VJP**, while forward+VJP time increases **57.79→63.70 ms**; this is not a universal speedup. In the synthetic harness, forward peak is read **before** error/validator diagnostics; the later VJP measurement includes live diagnostic tensors in its allocation baseline. Five repeats on one reported device are not independent timing trials. The accuracy comparison changes both early bandwidths and the number of moving levels, so it does not isolate the contribution of 129²/257² updates: that needs a fixed early-width `(.12,.06,.03)` refinement-only control. The current evidence establishes this complete schedule's synthetic improvement, not arbitrary fine-detail recovery or real-image generalization. No remote GPU jobs or implementation edits were performed by this checker.

## Independent matched-control and real-map follow-up

The matched-width experiment **closes the missing-control request in the preceding review**. Thus the document correctly retracts attribution of the original improvement to fine movement: under these fixed early widths, the additional fine updates worsen both errors. This is not a general impossibility result for fine-level updates.

All **six new saved maps** independently pass arbitrary-precision integer tests at every one of their **262,144 Q1 corners**, with exact identity residual boundaries.
