# Interpreting the same safe vertex table as a fixed-diagonal P1 map

## Predeclared research card

**Question.** The current fast forward decoder stores a Q1 bilinear map on a 257² rectangle grid, whereas the long-term objective also asks for a **piecewise-affine P1 homeomorphism**. Does the exact same stored vertex table define a guaranteed fixed-triangulation P1 homeomorphism, and how much does switching the interpolation rule change landmark accuracy on the three development pairs?

**Exact claim under test.** In a square with target vertices \(a,b,c,d\) at SW,SE,NE,NW, split along SW–NE. For normalized source coordinates \((s,t)\), define \(P(s,t)=a+s(b-a)+t(c-b)\) when \(t\le s\), and \(P(s,t)=a+s(c-d)+t(d-a)\) when \(t\ge s\). The two formulas agree on the diagonal and have positive oriented determinants equal to the already checked corner forms \(q_{10}\) and \(q_{01}\) (up to the positive source-cell scale). Across adjacent cells values agree on shared edges because both methods interpolate the same endpoint values. With the established ordered identity boundary, this yields a global P1 homeomorphism of the closed square; a separate positive output affine postcomposition preserves that property. The Q1 and P1 maps generally differ inside each cell, so prior Q1 landmark metrics must not be silently transferred to P1.

**Assumptions.** Fixed SW–NE triangulation at the **declared 257² output grid**, stored binary32 vertex coordinates interpreted exactly, positive affine factor stored separately, all Q1 corner signs and identity boundary already certified. No arbitrary grid resampling or inferred triangulation. Landmark inversion is evaluated separately and read-only.

**What would falsify it.** A nonpositive P1 triangle sign in the saved archives, incompatible values across the diagonal/adjacent cells, nonunique inverse for a landmark that lies in the represented target region, or an accuracy change large enough that Q1 metrics are an unreliable proxy for deployed P1 use. The theorem does not require equal Q1/P1 accuracy.

**Smallest decisive test.** Unit-test both triangle formulas on an affine map and a non-affine quad, including their shared diagonal. Then implement a separate P1 inverse evaluator for stored factorized maps, cross-check identity/affine fixtures and all three previously saved forward-kernel maps against the existing Q1 evaluator on the same original-JPEG landmark files. Report complete inverse-root coverage, TRE, Q1–P1 prediction displacement, and exact stored triangle signs. Do not change trained maps or tune parameters based on P1 labels.

## Planned differentiable P1 interface

**Question.** The evaluator above proves and measures a P1 *meaning* of saved Q1 vertices, but a downstream neural network still needs a concrete tensor layer with fixed face indices, batch support, fixed-query P1 sampling and a gradient to latent matches/affine factors. Can this be provided without flattening the positive-affine factor into an uncertified rounded composite vertex table?

**Exact interface claim.** A map object holds batch residual vertex tables \(U_b\in\mathbb R^{N\times N\times2}\), the **procedural** shared SW–NE face rule \(F\in\mathbb Z^{2(N-1)^2\times3}\), and each sample's positive-determinant output affine \((A_b,t_b)\). The full index table need only be materialized for mesh export; retaining it at 4097² would waste hundreds of megabytes. The object denotes \(\Phi_b(x)=A_b P_1[U_b,F](x)+t_b\), which is still P1 on the declared fixed triangulation. For fixed source queries \(q\) in triangle \((i,j,k)\) with barycentric weights \(\lambda\), \(\Phi_b(q)=A_b(\lambda_iU_{b,i}+\lambda_jU_{b,j}+\lambda_kU_{b,k})+t_b\). Consequently the VJP to the three vertices is the scatter of \(\lambda A_b^T g\); a decoder-to-match gradient follows by chain rule. Fixed face selection is independent of learnable vertices, so no dynamic triangle search is needed for forward image queries. Inputs may have non-smooth dependence at query points on grid edges but vertex/affine gradients remain defined for the chosen face.

**Decisive test.** Implement one small `torch.nn.Module` that accepts a batch of finite match coordinates, invokes the existing safe forward decoder independently per sample, and returns the factorized P1 object above with a lazy face-index generator. Compare its query values with the NumPy P1 evaluator on affine and nonaffine fixtures, test batch isolation and source/target/affine VJPs, and verify saved-binary sign certificates for representative outputs. This is an interface/proof alignment test, not evidence of learned image-to-latent generalization or high-resolution batch throughput. The module must not claim a flattened float32 composite table inherits the factorized certificate without a separate audit.

**Predeclared layer cost check.** On a free A6000, measure batch one and two with 257×257 *control vertices* and 512×512 fixed pixel-center P1 queries, float32 and 96 synthetic latent matches per sample. Use independent smooth, small, identity-boundary match motions for two samples and positive affine output factors. Two warmups and five synchronized repetitions measure (a) decoder plus P1 query plus affine forward and (b) the same forward plus one scalar loss backward to every match source/target and affine parameter; record CUDA allocated peak, not reserved memory. Save each residual table and audit its binary32 signs. No CNN, image intensity sampling, or external matcher is included, so this is a geometry-layer throughput test, not full image-to-map latency.

The batched `SafeSparseMatchP1Layer` now returns a factorized P1 object: residual vertices, positive output affine and the procedural SW–NE face rule. `evaluate_factorized_p1` chooses a fixed face from each **source** query coordinate, interpolates exactly three vertices and postcomposes the affine. It does not choose a face from the deformed target or materialize the entire triangle index table unless explicit export is requested. Its 2×2 nonaffine fixture agrees with the separate NumPy P1 evaluator to `1e-14` absolute; a batch-two fixture confirms different outputs and finite VJPs to source/target matches and affine factors. The module loops over batch elements at the present implementation stage, so batch scaling should be measured rather than assumed linear or fully vectorized.

The declared GPU test completed on then-idle AI-server A6000 GPU0, one float32 map per sample at **257² control vertices** and **512² fixed image-query centers** (262,144 queries/sample), 96 synthetic correspondence latents/sample. Three safe motion levels 17²/33²/65² were refined without further motion to 257². The sampled objective was a scalar squared-map loss; no image intensity, encoder, external matcher, JPEG loading, optimizer step or mesh inverse was included. Two warmups preceded five synchronized timed repetitions. CUDA memory numbers are *allocated peaks* in the benchmark process, not reserved memory or total board use.

## Independent verification

The forward formulas and barycentric inverse are correct for the **a–c diagonal**: lower/upper Jacobians are respectively `det(b-a,c-b)=q10` and `det(c-d,d-a)=q01`, divided by positive source-cell area. Both branches reduce to `a+s(c-a)` on the diagonal. Shared grid edges interpolate identical endpoints. Positive face signs plus the injective ordered boundary give degree one on the disk: generic interior targets have one positively oriented preimage, and continuity/local fan structure extend the conclusion across edges and vertices. Positivity alone is not the global theorem. Affine postcomposition preserves P1 and orientation when its determinant is positive.

Independent integer arithmetic on the exact saved residuals finds **131,072/131,072 positive triangle signs per map**. Minimum normalized lower/upper face determinants are **`.4582637351/.4388102689`**, **`.7800531046/.7790808851`**, and **`.7460673889/.7368288175`** (HistoReg/lesion/kidney). The separately audited exact boundary and positive affine factors supply the remaining global hypotheses.

I inverted the affine factor first, then solved each candidate residual triangle using independent 2×2 linear systems rather than the evaluator's cross-product inverse. All **77/77, 78/78, 69/69** roots are unique. Mean TRE is **25.7404993302994 / 8.1244752321169 / 7.4368994878915 px**, with at most `1.99e-12` px per-label discrepancy. Independently computed mean/maximum Q1–P1 predicted-location differences are **`.0003845073/.0018735194`**, **`.0000849833/.0006792818`**, and **`.0001331106/.0009586413`** fixed-JPEG pixels, confirming the table. Shared diagonals, outer corners and grid edges return one deduplicated identity inverse; both repository tests pass.

Three deliberate counterexamples delimit the claims. (1) For convex `a=(0,0), b=(1,0), c=(1.2,1), d=(0,1)`, P1 and Q1 differ by **.05** at the cell center; target `(.55,.5)` has P1 inverse `(11/24,1/2)`, not Q1 inverse `(1/2,1/2)`. In general, writing `C=c-b-d+a`, **`P-Q=C*(min(s,t)-s*t)`**, hence the within-cell difference is bounded by `||C||/4`, not identically zero. (2) A 3² identity-boundary table with center moved to `(1/8,1/8)` has all chosen P1 face areas positive (minimum double area `.0625`) but a Q1 corner determinant **−.125**. Thus the sufficient Q1 certificate must not be inferred from only two P1 faces. (3) The 17² sampled map `((1+x)cos(4πy),(1+x)sin(4πy))` has all P1 faces positive yet two distinct inverse roots, because its boundary is not injective.

The exact guarantee concerns the stored residual-plus-affine P1 interpretation; numerical inverse tolerances and float64 affine materialization are not a separate exact proof. The implementation is a read-only NumPy evaluator, not a newly implemented differentiable P1 image-warp or inverse layer. Fixed-query barycentric VJP is a mathematical observation here; dynamic inverse-face selection is not thereby smooth. No remote GPU jobs or implementation edits were used for this review.

## Independent tensor-interface check

The new Torch interface was independently checked on CPU, separately from the earlier read-only NumPy inverse review. Row-major cell indices are `a=rN+c, b=a+1, d=a+N, c_NE=d+1`; the emitted faces `(a,b,c_NE)` and `(a,c_NE,d)` are positively oriented for coordinates whose second component increases with row. This “SW–NE” name is a coordinate convention, not a claim that JPEG row coordinates point physically north. The query formulas have barycentric weights `(1-s,s-t,t)` below the diagonal and `(1-t,s,t-s)` above it, followed by **affine postcomposition**, not the reverse order. Source endpoints at one use the last cell with local coordinate one. All 32 faces of an independent 5² identity fixture had correct bounds and double area `.0625`.

Independent barycentric calculations reproduced query values and VJPs to vertices, affine matrix, offset and query coordinates with maximum error `2.23e-16`. A calibrated batch-two end-to-end directional test jointly perturbed all seven input blocks (proposal source/target, calibration source/target, affine, offset, query) and agreed with central differences within `7.72e-9`. A loss using only sample zero produced **exactly zero** gradients on sample one in every input block. These are local derivative checks away from selection ties; query-coordinate derivatives on triangle/grid edges are branch derivatives, not a claim of global smoothness. The four current CPU unit tests pass.

**Failure fixtures and correction.** Review found that the original floating determinant input check could accept binary32 matrix `[[1.7181129455566406,.8094261288642883],[2.147641181945801,1.0117826461791992]]`: Torch reports `+2.3743539e-8` while the exact stored determinant is `-2.5601877951e-8`. The author replaced this gate with exact rational signs on the actual binary32/binary64 inputs; the rejection and regression test were independently confirmed. Only the validation copy is detached; the original affine remains in the gradient path. An obvious reflection and a query outside the unit square were also rejected. Separately, a manually constructed 2² object with `a=(0,0), b=(1,0), c=(-.5,.2), d=(0,1)` has an upper-triangle determinant `-.5` but still evaluates normally: **the dataclass/query routine is not a topology certificate**. Its guarantee requires a valid decoder-produced residual and verified affine; arbitrary manual construction or tensor mutation can violate those hypotheses.

Exact integer products after verified scaling of the stored residuals by `2^40` find **no nonpositive corner among all 786,432 corners** in the two benchmark archives (one plus two samples), with exact identity boundaries. The first sample is bitwise identical across batch-one and batch-two archives. Minimum normalized corner determinants are `.8207102606538683` for both first samples and `.8944048366247443` for the second batch-two sample. Exact-rational affine determinants are positive (`.9897000106677407` and `.9900000099092721`). Thus all three factorized stored maps satisfy the fixed-diagonal P1 theorem; rounded composite vertices or arbitrary resampling are not certified by this calculation.

Timing scope matches decoder + fixed P1 query + affine and, for VJP, a scalar-loss backward to matches/affine. It excludes input creation/cloning, file export, exact saved-map audit, faces export, image sampling and external matching. The affine input validation itself is inside forward; its new CPU copy/exact check therefore requires refreshed GPU timings rather than inheriting the old numbers. The two warmups in this harness are **no-gradient forward warmups only**, not backward warmups; allocated peaks include live inputs and any overlapping old loop outputs, not isolated incremental operator memory. Query coordinates are fixed in the GPU benchmark, so its VJP timing does not include query-coordinate gradients or calibration inputs, although those paths were checked in the independent tiny test above. No independent GPU timing rerun was performed by the reviewer.

The post-fix `p1_layer_exact_257_512query_*` report was subsequently checked read-only: its batch-one/batch-two forward and forward+VJP medians round to the updated table's **11.51/44.69 ms and 22.26/93.93 ms**, allocated peaks agree, and independent integer/rational re-audits confirm all **786,432** residual corners positive, exact identity boundaries and positive affine determinants across three members; all saved geometry arrays are bitwise unchanged from the earlier archives, with no GPU rerun by the reviewer.
