## Named question E0: Do old P1 or center-only checks certify the deployed Q1 map?

No. The exact rational fixed-boundary fixtures in `TOPOLOGY.md` have respectively (A) all old SW–NE P1 triangles positive while one Q1 corner is negative, and (B) positive center checks while Q1/P1 have negative corners. A separate checker reproduced the arithmetic without calling the production determinant helper. These are logical counterexamples to transferring an old certificate; they do not indicate a defect in the old P1 theorem.

## Named question E1: Do the first F1-D/F2-D implementations preserve Q1 corners and propagate their actual gradients on tiny grids?

The newly added `digital_q1.py` implements four-corner Q1 evaluation, exact dyadic Q1 nodal refinement, F1-D 12-constraint colored updates, and F2-D four-corner patch updates. A single patch across the domain now runs one pass because no shifted seam exists; larger grids use four staggered passes. `validate_q1_map` audits the supplied actual tensor in bounded row chunks and never silently substitutes an identity map. It does **not** provide an outward-rounded IEEE sign proof.

On local Windows Python 3.12.4 / PyTorch 2.5.1+cpu, the command below returned **12 passed** (2026-09-28 UTC):

```powershell
$env:PYTHONPATH=(Resolve-Path -LiteralPath 'src').Path
python -m pytest tests/test_digital_q1_geometry.py tests/test_digital_q1_independent_checker.py tests/test_digital_q1_benchmark_smoke.py -q
```

The independent checker compared a separate NumPy Q1 derivative enumeration with the torch output, confirmed float64 F1-D/F2-D directional VJPs by three central-difference step sizes, and rejected a deliberately detached F2 safety scale. An additional pre-existing regression command (with `src;tools` on `PYTHONPATH`) returned **25 passed** for the old F1/P1 and F2/P1 suites; the new code does not reinterpret old checkpoints.

These tiny tests support an implementation claim on the tested cases only. The exact-arithmetic theorem assumes an initially valid Q1 map and a simple ordered boundary. Current update classes assume a **square, uniform unit source grid**. Their optional minimum Jacobian floor is conditional on the input already meeting it. Nonfinite inputs, saved/cast outputs, and uncertain floating-point corner signs require separate deployment checks.

## Next medium-scale measurement protocol

`tools/digital_q1_benchmark.py` creates an identity map on an actual `N×N` control-vertex grid, one batch of deterministic Gaussian latent proposals (seed 290929, logit standard deviation 0.15), and a fixed random cotangent. Mode `f1` applies four sequential vertex colors to **one** latent field; mode `f2` applies four shifted patch passes with **four** latent fields. These are distinct workloads, not a same-parameter architecture ranking. The script warms once, then reports synchronized medians of pure geometry forward and VJP-to-all-latents separately, minimum of all `4(N-1)^2` unnormalized Q1 corner determinants, nonpositive/nonfinite count, boundary error, gradient finiteness/magnitude, and CUDA allocated/reserved peaks. It excludes image encoder, I/O, final warp, saving, and any true registration metric.

At the initial remote read-only check, `ai-codex-mihomo-codex` was reachable with `ClearAllForwardings=yes`; GPUs 0, 2, 6, 7 were RTX A6000 49,140 MiB total with 48,660 MiB reported free and 0% utilization, while GPUs 1, 3, 5 were busy. This was an instantaneous snapshot, not a standing reservation. GPU process IDs were read and no other process was stopped. The `cuda124` environment provides PyTorch 2.5.1+cu124. Occupancy will be rechecked immediately before launching medium jobs.

The first export attempt used `torch.save` and failed inside the remote PyTorch serializer (`_pickle.Pickler.persistent_id` read-only) under its Python 3.13.0 / PyTorch 2.5.1+cu124 environment; local Python 3.12.4 did not reproduce it. That artifact was copied to [q1_257_f1_float32.npz](q1_257_f1_float32.npz) on D:. A separate local NumPy test recalculates all corners directly from the **saved binary32 coordinates converted to binary64** rather than using the production helper; it passed. This is evidence for this one exported sample, not yet a rigorous floating-point sign certificate for every possible latent or an actual pathology registration output.

An additional independent checker evaluated every one of the saved map's 262,144 corner signs as exact integers representing the saved binary32 coordinates. The filtered validator uses outward-expanded binary64 intervals and exact rational fallback for ambiguous signs; its interval path was cross-checked against rational arithmetic on 900 adversarial/random binary64 triples, including overflows and subnormals. This is a certificate of **this stored sample** under correctly rounded IEEE binary64 operations, not a proof that all network outputs will survive binary32 rounding. A deliberately twice-wrapped annular map showed that four positive corners per cell, even for every cell, do not imply global injectivity if the boundary is not simple. Both the tensor and saved-binary validators now require an explicitly ordered, axis-aligned rectangular reference boundary as well as equality to that boundary; they reject empty batches. The narrow boundary condition matches the current fixed-canvas decoder but does not certify arbitrary curved boundary data.

## E1 extension: mixed Q1 pyramid and pixel-center sampling

`HybridPatchSeedVertexQ1Pyramid` applies F2-D to a coarse seed and F1-D to only the new vertices at each dyadic level. `q1_dyadic_refine` represents the previous Q1 function exactly in ideal arithmetic; the decoder edits one final Q1 vertex table, without interpolating a composition of separately sampled maps. Local tests cover identity, non-affine refinement, strict four-corner positivity for finite example fields, fixed boundary and VJP to both seed and level latents. An image encoder's zero-initialized heads feed the mixed decoder; a loss on a new fine vertex has a nonzero gradient to the corresponding head. A loss placed only on an old even/even vertex gives zero gradient to that level by design, which the test initially exposed.

For real image use, `q1_image_sampling.py` distinguishes the fixed-image pixel centers `((j+1/2)/W,(i+1/2)/H)` from control-grid vertices `((j)/(N-1),(i)/(N-1))`. It evaluates the map by bilinear Q1 interpolation (`align_corners=True` on the vertex table), then evaluates moving-image intensity by bilinear pixel-center sampling (`align_corners=False`). Identity and analytic-cell tests pass. This is a defined image-sampling convention, not a digital-topology certificate for a regridded map. Earlier Phase VII synthetic results used endpoint image samples and `align_corners=True` throughout; their numbers are not silently reinterpreted under the new convention.

### Same-pair image-only Q1 latent optimization: photometric gain, geometric failure

Named question: when the *same safe Q1 decoder* is optimized directly on one real CD68 moving → CD4 fixed image pair, without a CNN or landmarks in the optimizer, do image alignment and landmark alignment improve together? `tools/digital_q1_real_optimize.py` resampled each whole supplied JPEG separately to a 512×512 pixel-center, unit-square grayscale image. It initialized all 17² F2 seed and 33²–257² new-vertex F1 latents at zero and optimized them for 100 Adam steps at learning rate .04. The objective was global `1−NCC` between the fixed and warped moving thumbnails plus `.05 mean ||Phi−id||²`; NCC is normalized correlation, **not** image MSE. The map is fixed-normalized → moving-normalized, with identity boundary. GPU was the then-idle AI RTX A6000 GPU0, PyTorch 2.5.1+cu124, batch 1, float32. Median complete training step was 68.94 ms, including map, warp, loss, backward and Adam; peak CUDA allocated memory was 94.8 MB. First → best measured `1−NCC` was `.265013 → .092968`; 100/100 steps had finite latent gradients.

The saved [257² Q1 map](q1_real_O_257_float32.npz) was copied back to D: and its **stored binary32 values** independently passed the filtered sign audit: all 262,144 cell-corner determinants strictly positive, ordered identity boundary and no rejected cell. `tools/digital_q1_real_eval.py` separately read the 77 public example landmarks *after* optimization, converted pixel centers by `(x+.5)/W,(y+.5)/H`, enumerated inverse Q1 roots and found one per landmark with maximum unit-coordinate reconstruction residual `1.57e−16`. All 77 predictions lay in the fixed image. The table below is **one development pair at provided JPEG resolution**, not held-out or physical-unit performance.

### Next predeclared H-mode test: safe distillation of a strong image-only field

**Question.** Is the poor O-mode TRE chiefly due to inference/objective choice, or does the safe 257² Q1 decoder lack the capacity to express an anatomically useful field on this pair? Fit the safe decoder's latent variables to the **saved, image-only DHR fixed→moving field** sampled at Q1 control vertices, using vertex-coordinate MSE and no landmarks. This is a hybrid/teacher-distillation diagnostic: DHR remains part of inference and supplies the target; it is not an independent network, a fair runtime competitor, or evidence of generalization. Record the DHR sampled target's own four-corner signs, decoder-to-target vertex error, actual saved-map certificate, image score, landmark TRE, training time and memory. Keep the identity boundary required by the present Q1 theorem; any boundary mismatch is measured, not hidden. If 257² retains poor landmark accuracy or high target error, inspect boundary/expressivity before trying 1025². If it succeeds, it only establishes that the safe representation can absorb *this* image-derived teacher, motivating separate network inference on multiple group-separated pairs.

The 257² test ran on the then-idle AI RTX A6000 GPU0, batch 1, float32. `tools/digital_q1_dhr_distill.py prepare` converted the saved DHR field to fixed→moving normalized coordinates at actual Q1 control vertices, with the two original JPEG sizes and DHR's recorded scale/pads. Its [sampled target](dhr_teacher_257_float32.npz) had **zero nonpositive Q1 corners** at this coarser grid but a maximum boundary disagreement of `.103657` unit coordinates and **256 target vertices outside** the moving unit square. These facts do *not* rescue the original 747×991 DHR output's 7,108 folded Q1 cells or make the sampled target a homeomorphism onto the unit square. They also mean the identity-boundary Q1 decoder cannot exactly reproduce this target.

All latent fields of the 17² F2 seed → 33²–257² F1 pyramid were optimized directly against the target's **strict-interior vertex coordinates** for 200 Adam steps at learning rate `.04`. The interior vector RMSE was `.057973` at zero latents and `.0081875` at the best saved step; median complete step 67.27 ms, peak CUDA allocated 88.2 MB, 200/200 finite gradient steps. The saved [H-mode Q1 map](q1_h_dhr_distill_257_float32.npz) has ordered identity boundary, zero nonpositive corners in both the tensor audit and the stored-binary certificate. In the same 77-point development diagnostic, 77/77 moving landmarks had a unique inverse, and 77/77 predicted fixed points lay inside the JPEG. Mean/median/P95/max TRE were **32.551/18.050/85.482/256.173 pixels**. On the same 512² grayscale thumbnail protocol, this H map's `1−NCC` was `.117402`, **worse** than both DHR's `.104813` and the anatomically much worse O map's `.0929675`. This reinforces that this image score cannot rank anatomical accuracy on the pair. The H result is not a runtime improvement over DHR because generating its teacher field still requires the baseline's 77.03-second pipeline; the 67-ms number times only an extra optimization step.

An independent checker inverted both the raw sampled teacher and the H map with a separate numerical method. The **257² sampled teacher**, despite its invalid/out-of-square boundary and therefore **without** a global topology certificate, had 77 unique landmark inverses and mean/median/P95/max TRE **14.497/12.043/35.432/63.197 pixels**. This is close to the original field's 14.2325-pixel mean: 257² sampling itself accounts for little of the H map's 32.55-pixel mean. The checker also reproduced the H map's 32.551-pixel mean and independently found all stored-binary Q1 corner signs positive. The remaining gap is introduced by the identity-boundary safe-fit stage in aggregate, but the effects of boundary restriction, optimization, and decoder expressivity are **not yet separated**. Do not tune these against the already viewed 77 development labels and then describe the result as held-out.

The checker found larger *vertex-fit* residuals near the fixed boundary (unit-coordinate vector RMSE `.01747` for interior nodes with boundary distance below `.05`, versus `.003623` for distance at least `.1`). That does not by itself explain the landmark outliers: the two largest H TREs, 256 and 208 pixels, occur at labeled fixed points about `.25` unit from the nearest edge. The descriptive correlation between 77 TREs and edge distance was weak (Spearman `−.124`). A boundary restriction may propagate into the interior through the decoder, but the data do not establish that causal path.

**Predeclared affine-factorization test.** Regress a positive-orientation global affine map `A(x)=Mx+b` against *all image-only teacher vertices*, then fit the unchanged identity-boundary safe decoder to `A^{-1}∘T`. The actual represented output is `A∘U`, where `U` is the safe Q1 residual map. Since `det M>0`, this is exactly Q1 in ideal arithmetic and a homeomorphism from the unit square onto the parallelogram `A([0,1]²)`. It need not map into the moving image square; record out-of-source queries. This is a **different output-boundary contract** from the preceding identity-boundary result and must be labeled separately. The affine fit uses no landmarks. A read-only 3×3 least-squares diagnostic found `M=[[.93640,.14401],[-.06984,.95538]]`, `b=(-.03711,.03136)`, `det M=.90468`; the residual target's boundary max discrepancy drops from `.10366` to `.04269`, and its strict-interior vector RMS from identity drops from `.05797` to `.00783`. This motivates, but does not validate, the new fit. The decisive observations will be residual fit RMSE, saved residual binary certificate, exact sign of the stored affine determinant, full composite-field inverse TRE, image loss, and whether final materialization preserves the boundary/topology claim. No held-out advantage is inferable from this one teacher pair.

The test completed at 257², batch 1, float32 residual coordinates and affine coefficients. The same AI RTX A6000 GPU0 and 200 Adam steps at `.04` reduced residual-target strict-interior vector RMSE from `.0078323` to `.00093224` unit; median complete step **67.64 ms**, peak CUDA allocated **88.2 MB**, all 200 latent VJPs finite. It does not store a separately rounded composite vertex table as the authoritative output. The residual's 262,144 stored-binary Q1 corner signs are positive and its boundary is the exact identity rectangle; the stored affine determinant is **exactly positive** (`2037155625597927/2251799813685248` when its binary32 coefficients are interpreted as rationals). Therefore the represented composition `A∘U` is Q1 and globally homeomorphic onto its affine parallelogram. The independent checker applied `A^{-1}` first and inverted `U` through a separate cell solver; all 77 inversions were unique, with mean/median/P95/max TRE **14.559/12.066/35.284/63.070** supplied-JPEG pixels. Its mean is close to the raw sampled teacher's **14.497** and original DHR field's **14.233**, unlike the un-factored identity-boundary H map's **32.551**. On the same 512² inverted-grayscale appearance protocol, this affine-H composition has `1−NCC=.107787`, grayscale MSE `.00127770`, and exploratory `.08` foreground Dice `.921264`; **1,428/262,144** fixed-image query centers map outside the moving unit square and receive border sampling. The original DHR field's corresponding NCC/MSE/Dice were `.104813/.00125585/.923386` with 65 outside-source queries. The 67-ms step also excludes the DHR teacher generation, which still cost 77.03 seconds in the reduced CPU baseline. G2 independent network inference and G3 held-out real-data accuracy remain untested.

Certificate semantics matter here. `certify_q1_binary_map` audits only the stored **residual** Q1 vertices; the fit command now labels that result `saved_binary_residual_valid`, not `saved_binary_valid` for the entire composition. `digital_q1_real_eval.py` additionally checks the stored affine determinant with exact rational arithmetic before reporting `composite_representation_valid`. A freshly materialized and rounded composite vertex table would be a *different* numerical artifact and would require its own four-corner and simple-boundary audit; that has not yet been done. The [independent review](REVIEW_REAL_Q1_O.md) confirms the exact stored-factor and 77-point calculations, not a theorem about arbitrary future float32 network outputs.

### Two additional public histology development pairs: representation versus inference

**Question.** Does the safe 257×257 Q1 representation preserve an anatomically useful strong field on *other* pathology pairs, and do image-only optimization or a frozen image-to-latent network recover it independently? These are two public BIRL/ANHIR sample sets, not a sufficient train/validation/test collection. Exact files, dimensions, 5%-scale status, terms and labels are in [DATA_NEXT.md](DATA_NEXT.md). The lesion set is HE fixed 890×733 versus proSPC moving 891×735 with 78 matched points. The rat-kidney set is HE fixed 1164×787 versus PanCytokeratin moving 1123×724; 69 IDs match and fixed-only IDs 70–71 are disclosed and excluded. Images alone were used for registration and teacher generation; landmark CSVs were read only by a later evaluator. Both sets are now *inspected development examples*, not blind held-out tests.

Every Q1 candidate uses **66,049 control vertices** and a 512×512 independently resized inverted-grayscale image for fitting/inference. Its actual map is evaluated continuously by Q1 interpolation; 512² image pixels are **not** 512² control vertices. For a moving landmark \(m_k\) in its original JPEG and a fixed landmark \(f_k\), the reported target registration error is

\[
\operatorname{TRE}_k=\left\|\operatorname{pixel}_{W_f,H_f}\!\left(F^{-1}\!\left(\operatorname{unit}_{W_m,H_m}(m_k)\right)\right)-f_k\right\|_2,
\quad \operatorname{unit}_{W,H}(x,y)=((x+\tfrac12)/W,(y+\tfrac12)/H),
\quad \operatorname{pixel}_{W,H}(u,v)=(Wu-\tfrac12,Hv-\tfrac12).
\]

The evaluator enumerates Q1 inverse roots rather than silently assuming invertibility. A method's full mean TRE is **undefined** if any matched landmark has zero or multiple inverse roots; conditional-on-unique means are supplementary only. `Identity` below means the unit-square identity, which correctly accounts for different JPEG dimensions, not raw pixel-coordinate identity.

The reduced DeeperHistReg CPU baseline was run at native sample JPEG loading scale 1, with 768-pixel preprocessing minimum resolution and the same 150 nonrigid iterations used for the HistoReg development run. Complete pipeline time was 21.30 s (lesion) and 22.70 s (kidney), including SuperPoint/SuperGlue initialization. Its saved field had **473/653,260 lesion cells** and **140/869,778 kidney cells** failing at least one of the four Q1 corner determinants; the per-corner counts are in the D: evaluator JSONs. The kidney field's preprocessing factor was 1.0247395833333333 = 787/768: the saved field remains on the preprocessed 768×1135 grid. For an original moving pixel center \(x\), the evaluator first applies loading scale and padding, then \(x_{\mathrm{field}}=(x_{\mathrm{padded}}+1/2)/r-1/2\), inverts the saved field, and reverses these steps for fixed coordinates. **Image-dependence and inference cost.** The frozen 1,000-step model was also run on the original pair, the two BIRL pairs, their input-swapped versions and blank/blank inputs. Peak CUDA allocated/reserved were **35.5/58.7 MB**. This excludes JPEG decode, CPU transfer, saved-output certification and landmark inversion; the timed image warp uses a freshly materialized float tensor, while the verified topology contract applies to the stored residual-plus-affine representation. The speed is promising engineering evidence for a *forward layer*, but the present N accuracy and coverage failures prevent calling it a useful end-to-end registration system.

**Current technical inference.** On three inspected real pairs, the 257² safe affine-plus-Q1 representation is not the dominant obstacle: teacher-conditioned fits retain strong landmark accuracy while eliminating sampled four-corner failures. The unresolved obstacles are (i) an image objective/feature pipeline that identifies correct cross-stain correspondences, (ii) a network trained on genuinely distinct groups, and (iii) a domain-coverage contract if an affine parallelogram may leave the moving image rectangle. None of these are solved by the current one-pair CNN. The [independent BIRL review](REVIEW_BIRL.md) found no metric discrepancy; it does not elevate two inspected sample groups to a generalization study.

### Three-pair leave-one-out network pilot: image dependence does not imply useful transfer

**Question.** Is training the same image-to-safe-Q1 network on two *different* public pathology examples sufficient to transfer an image-derived deformation to a third? This is a **development pilot**, not a patient/block-held-out or statistically powered G2 test: only three sample groups are available, their patient/block relationships are not all authoritative, and all three public landmark sets had already been inspected during development. The fixed/moving image pair and precomputed **image-only** DHR teacher map for each of the two training groups enter the batch; no landmark CSV enters `tools/digital_q1_network_group_pilot.py`. For each fold, a newly initialized width-16 encoder, 17² F2 → 33²–257² F1 safe decoder and positive-affine head are trained for **800 Adam steps at .002**, batch 2, 512² inverted-grayscale thumbnails, mean squared vector error against both teacher vertex tables. The third group's teacher and landmarks are absent from training and inference. The trained network is frozen before it sees the third pair's images; afterward the read-only evaluator uses the already-public landmarks. Thus the protocol is a small leave-one-example-out engineering check, not a blind test claim.

The final reproducible folds ran on then-idle AI RTX A6000 GPUs 0, 2 and 6, respectively, with PyTorch 2.5.1+cu124 and float32. Complete batch-2 steps took median **83.36/75.39/82.04 ms** and each peaked at **263.0 MB CUDA allocated**; each had 800/800 finite full-network gradient steps. Best training map vector RMSE was `.006010` for BIRL lesion+kidney, `.003220` for HistoReg+kidney, and `.007154` for HistoReg+lesion, in normalized coordinate units. The exact fold membership, seed and settings are in the adjacent `*_train.json` files; `*_infer.json` and `*_eval.json` are the frozen-inference and landmark audit outputs. An initial serial GPU0 run had slightly different numerical weights and was replaced by this saved-report rerun; do not mix its numbers with the final maps. Every frozen saved residual was audited at its 262,144 Q1 cell corners and exact identity boundary, with zero nonpositive corners; every stored affine determinant was positive. The composite is a homeomorphism *onto its predicted affine parallelogram*, not necessarily onto the moving image square.
