# Image-encoder sanity test: held-out texture with known synthetic translation

## Research card, declared before implementation

**Question.** Can the existing width-16 image-to-safe-Q1 network infer a known global translation from a pair of *same-source* real histology thumbnails, then transfer that inference to an unseen underlying texture?

**Exact claim under test.** After training on two source JPEGs with randomly translated copies as moving images, the network's held-out map-vector root mean square error (RMSE) should improve substantially over an identity-map predictor on the third source. This is a necessary-but-not-sufficient perception check, **not** G2 on real cross-stain registration.

**Assumptions.** Resized grayscale pixels define a continuous bilinear image by `grid_sample(..., align_corners=True)`. For a sampled shift (t\in[-.06,.06]^2), set moving (M_t(u)=F(u-t)), with border extension. Then the intended fixed-to-moving sampling map is (T_t(x)=x+t) wherever image content is unambiguous. The target map is an exactly representable positive-affine translation of the identity Q1 residual. At crop boundaries the photometric relation may be uninformative, but target-coordinate error remains defined.

**What would falsify it.** Held-out coordinate error similar to or worse than identity; a model that predicts the average shift regardless of input; nonfinite full-network gradients; or invalid saved Q1/affine output.

**Smallest decisive test.** First unit-test the shift direction on a monotone synthetic ramp and a tiny finite-VJP training call. Then use the three already inspected JPEG texture sources, two for training and one for held-out evaluation, with random shifts generated online. Run one 257²-control-grid pilot fold with image side 128, batch 4 and up to 800 Adam steps. Draw 64 deterministic held-out shifts with a separate seed. Report map-vector RMSE versus identity, affine-offset error, an image-input ablation, complete step time, GPU allocated peak, and residual/affine topology. If the pilot fails, diagnose the existing local CNN/global-pooling bottleneck before building a correlation head; if it succeeds, repeat all three leave-one-texture-out folds. Landmarks remain entirely absent from training and evaluation here; these translations are not independent pathology registration cases.

**Prior work.** Classical cross-correlation or phase correlation can solve same-modality translation; success here is a basic network sanity check, not novelty. The prior three-teacher leave-one-out failure on actual cross-stain pairs remains the relevant real-image warning.

## Implementation, metric and measured result

`tools/digital_q1_synthetic_translation.py` uses one fixed-source grayscale JPEG per source group: HistoReg CD68, BIRL lesion HE, and BIRL rat-kidney HE. Each is independently resized to **128×128 image pixels**. For every online training step, two of these underlying images supply a batch of four independently drawn translations in ([-.06,.06]^2) unit-square coordinates; the third source JPEG is absent from training. The same width-16 `Q1ImageRegistrationNetwork` predicts a 257×257-control-vertex safe Q1 residual (U), a positive-orientation affine matrix (A), and offset (b), returning (Phi(v)=A U(v)+b). The target at every control vertex is (v+t). All network parameters receive true gradients through the safe decoder; no image labels, landmarks, DHR teacher fields, or target maps from real registration enter training. Each fold uses 800 Adam steps at learning rate .002, seed 290929, batch 4, and one then-idle RTX A6000 (GPU0 or GPU2). A shift in normalized image coordinates corresponds here to (t_x(128-1)) or (t_y(128-1)) pixel-center spacings because `align_corners=True`; this self-contained synthetic convention is **not** silently substituted for the DHR/JPEG `align_corners=False` convention used in real-pair evaluation.

For (K=64) independently seeded held-out translations and (N=257^2) control vertices, define the map-vector error

\[
E_{\mathrm{map}}=\sqrt{\frac{1}{KN}\sum_{k=1}^K\sum_{v\in V_h}\lVert\Phi_k(v)-(v+t_k)\rVert_2^2}.
\]

The identity baseline replaces (Phi_k(v)) by (v). `shuffled` cyclically permutes the moving images among an evaluation batch of eight while keeping their original fixed images and targets; `blank` gives the network two zero images. These are input-dependence probes, **not** anatomical correspondence metrics. Affine-offset error is the root mean squared Euclidean difference between the predicted (b_k) and (t_k), although part of a translation could also be carried by (U_k) and (A_k), so this is only a diagnostic. Training-step time starts **after** synthetic moving-image and target construction, and includes forward, loss, full backward and Adam update; preprocessing and online augmentation are excluded. `best_train` in the JSON reports is the minimum among different online minibatches; the saved weights are from the **final step**, not that minimum.

| Held-out underlying texture | (E_{\mathrm{map}}) | Identity (E_{\mathrm{map}}) | Reduction | Shuffled / blank (E_{\mathrm{map}}) | Affine-offset error | Median train step / allocated peak |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| HistoReg CD68 | **.026381** | .051414 | 48.69% | .058913 / .052102 | .028596 | 74.71 ms / 362.9 MB |
| BIRL lesion HE | **.023322** | .051414 | 54.64% | .062697 / .050833 | .022792 | 74.83 ms / 362.9 MB |
| BIRL kidney HE | **.021975** | .051414 | 57.26% | .067754 / .055281 | .020281 | 84.39 ms / 362.9 MB |

All three folds completed **800/800 finite full-network gradient steps**. On all 64 held-out examples per fold, the in-memory residual audit found no nonpositive Q1 corners, an exact identity residual boundary and minimum positive affine determinants `.997916/.991666/.983598` (HistoReg/lesion/kidney). Only the **first** example of each fold was saved as a binary32 map; those three archives are stored on D: outside Git along with the final weight archives. A separate saved-file auditor found zero nonpositive residual corners and an exactly positive determinant of the stored affine coefficients in each of the three examples; hence each *stored factorized representation* passed its composite homeomorphism certificate. This is not a saved-file certificate for the other 63 maps of each fold. A frozen batch-one timing on the kidney-held-out model, with 20 repetitions after three warmups on the A6000, measured **18.44 ms** median image-pair→map forward and **18.34 ms** image-pair→map→128² image warp, 28.95 MB CUDA peak allocated; the tiny inversion of those two medians is ordinary timing jitter. These timings exclude JPEG decoding, host transfer, output certificates and any registration-landmark inversion. The input image has 16,384 pixels, whereas the map has 66,049 control vertices—neither number may stand in for the other.

**Interpretation.** The existing network clears this weak same-source translation sanity check on all three held-out textures, and shuffled inputs increase error; it is therefore capable of using image-pair cues in a simple setting. The shifted image's border extension creates visible cues, so the shuffle result alone does **not** prove internal histological-feature matching. The experiment does not test stain invariance, nonlinear real tissue deformation, independent patient generalization, or the G2 comparison against a strong no-network method. In fact, classical phase correlation is a strong expected competitor for this exact synthetic task. The earlier cross-stain leave-one-out pilot remains a failure of useful real-pair transfer; these new results do not overturn it. The immediate research need is a stronger, properly grouped cross-stain image frontend/dataset, not another random decoder-only speed claim.

## Post-pilot, predeclared shortcut controls

The positive three-fold result raises a narrower question: did the network exploit the translated image's border extension instead of matching internal histological texture? Freeze each final checkpoint and use the **same 64 shifts and textures**, without retraining. Zero the outer 12-pixel margin in both fixed and moving 128² inputs *after* generating each pair; this keeps the target (x+t) unchanged and removes the shift-specific source-image edge, but also creates a new input distribution, so degradation is suggestive rather than a proof of border cheating. Report both original and border-masked map RMSE for all three folds. In parallel, run OpenCV Hanning-windowed phase correlation on the same unmasked same-source pairs and convert its pixel shift to normalized units by dividing by 127; this is a nonlearned O-mode baseline for this **synthetic translation subtask only**, not a real cross-stain registration baseline. First verify its sign on a known translated fixture. If it dominates the CNN, do not present the synthetic pilot as evidence that learning is needed.

The sign fixture used a random 128² image shifted by ((4,-3)) pixel-center intervals and recovered the expected fixed→moving sign to within .004 normalized units. OpenCV was not installed in the original training environment; running the controls from another isolated environment initially changed JPEG thumbnail values slightly because its Pillow version differed. To remove that input mismatch, `tools/digital_q1_synthetic_texture_export.py` exported the **exact three 128² float32 thumbnails from the original training environment**; the final controls loaded these same arrays and reproduced each training report's original-map RMSE exactly to the printed precision. The three derived thumbnails are kept on D: outside Git, while the versioned JSON controls identify their paths. The numbers below are from this exact-input rerun, not the initial mismatched-JPEG diagnostic.

| Held-out source | Original network RMSE | Border-zeroed network RMSE | Hanning phase-correlation RMSE | Median phase-correlation call |
| --- | ---: | ---: | ---: | ---: |
| HistoReg CD68 | .026381 | .033173 | **.001362** | .219 ms |
| BIRL lesion HE | .023322 | .024802 | **.001390** | .220 ms |
| BIRL kidney HE | .021975 | .023042 | **.001362** | .199 ms |

The border-masked network remains below the .051414 identity error in every fold, so the observed predictor does not *solely* rely on the outer 12 pixels; the ablation does not identify what interior cue it uses or establish real cross-stain robustness. Phase correlation is far more accurate on all three simple same-source shift tasks. Its `.2`-ms timer includes its Hanning-window construction and OpenCV call on an already-decoded 128² pair, but excludes JPEG loading, synthetic image creation and building/saving a 257² factorized map; the 18.44-ms neural timer includes its safe Q1 decoder and a different GPU timing protocol. Thus this is a decisive **accuracy** counterexample to needing the learned model for same-source translations, not a fully fair end-to-end latency claim. The scientific value of a learned frontend, if any, must come from more difficult cross-stain and deformable correspondences under an independent group split.

Independent review found that `cv2.phaseCorrelate` with the supplied Hanning window modifies its input float32 arrays in place. The original GPU controls read them from temporary host copies after network evaluation, so their reported metrics were unaffected; on a CPU path those arrays could alias the source texture and contaminate later batches. A new regression test first reproduced the mutation, then the helper was changed to make explicit contiguous copies. Repeating all three exact-input GPU controls with the corrected helper produced the **same RMSEs** and the final per-call timings in the table; the versioned JSONs are from that corrected rerun. This is a code-path correction, not a change in the scientific conclusion.

## Independent pilot check

The source and three reports agree on the held-out texture indices and the two training indices. Only training indices enter the loss; evaluation uses an independent shift seed, and no landmark or DHR field is loaded. The sign is correct: sampling `M(u)=F(u-t)` requires fixed-to-moving `x+t`. An independent rectangular 9×13 two-axis ramp fixture reproduced the generator within `4.45e-16`; using the correct target recovered the interior within `1.12e-16`, while deliberately reversing the target sign caused .25 maximum image error. The align-corners endpoint convention means shifts are multiplied by width/height **minus one**, not by image size.

For each final checkpoint I independently regenerated all 64 shifted images with **SciPy interpolation in pixel coordinates**, ran the frozen model on CPU, and computed full-map errors in float64 without calling the production evaluation or shift-generation functions. HistoReg/lesion/kidney RMSEs were **`.02638059080/.02332218271/.02197453804`**, identity `.05141416425`, shuffled `.05891278716/.06269732987/.06775369714`, and blank `.05210205467/.05083268701/.05528103447`. These and the offset errors agree with every report within `1.1e-8`; CPU/SciPy and original GPU maps are not claimed bitwise identical. A perfect translation oracle under the same cyclic shuffle would score `.07189969`, while a deliberately constant predictor's error is unchanged by shuffling: the ablation distinguishes paired-input dependence, not the specific visual cue used.

Every first-example saved residual independently has **262,144 strictly positive arbitrary-precision integer corner signs** and the exact ordered identity boundary. Exact rational determinants of the three saved affine factors are `73950077601970562621/73786976294838206464`, `36986629900913516911/36893488147419103232`, and `2319105021496422265/2305843009213693952`, all positive. Thus these three saved factorizations are homeomorphisms onto their affine parallelograms; the other 63 examples per fold have reported in-memory audits, not saved-file certificates. The helper's original `saved_example_certificate` field certifies the **residual only**; the separate affine calculation above is necessary for the full stored representation.

One additional interpolation caveat: the formula `M(u)=F(u-t)` is exact at generated moving-grid samples, but reconstructing that new raster and warping it back performs interpolation twice. A deliberately half-pixel-shifted unit impulse reconstructs with center intensity .5 rather than 1 even away from the outer border; target-coordinate supervision remains valid, but exact photometric inversion should not be assumed. Border extension may also supply shortcuts, 64 translations of one source are not 64 independent biological examples, `best_train` compares different minibatches, and reported training-step timing excludes pair synthesis as now documented. Three existing CPU unit tests passed; no GPU job or production-code edit was performed. The newly predeclared border-mask/phase-correlation controls are outside this completed pilot check.

## Independent exact-input controls check

The subsequent controls are now independently checked. Using the three saved float32 textures, SciPy pixel-coordinate interpolation for all 64 shifts, frozen CPU checkpoints, and direct OpenCV calls on explicit copies, I obtained border-masked RMSEs **`.033173083863/.024801563113/.023042139469`** and phase-correlation RMSEs **`.001361829606/.001390114064/.001362388590`** (HistoReg/lesion/kidney). Original-network errors also reproduce the pilot within `1.1e-8`; the exact-input control JSONs' original-error values equal the corresponding pilot JSON values. These checks support the reported accuracy ranking without calling the production control evaluator.

Two deliberate attacks exposed the relevant failure modes. Swapping phase-correlation arguments on a rectangular 96×128 image translated by `(4,-3)` pixels gives normalized error `.089374`, versus `.000245` with the correct order; dividing by image size rather than size minus one introduces an additional `.000411` normalization bias. Passing aliased contiguous float32 arrays to the original helper changed their values by more than 3, confirming the CPU texture-contamination defect. The corrected explicit-copy helper preserves both arrays, including an expanded shared-texture view, and both control tests pass. Independent recomputation supports the unchanged saved GPU accuracy numbers; the final JSON timing medians are `.219/.220/.199` ms.

The 12-pixel mask exceeds the maximum 7.62-pixel translation, removing the border-extension strip, but introduces common artificial edges and a distribution shift. Its result rules out exclusive reliance on the removed strip, not all shortcut cues or lack of border use in the original predictor. Phase timing includes protective array copies and window creation but excludes the preceding device-to-host transfer, pair synthesis and full-map construction; it is not an end-to-end speedup measurement against the neural GPU timer. No GPU jobs or production-code edits were performed for this independent check.
