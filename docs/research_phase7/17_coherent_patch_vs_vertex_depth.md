# 为什么 F2 不能被小位移 F1 速度排名淘汰：协调移动的深度对照

## 独立目标与安全性

[双分量高频实验](16_dense_two_component_f1_fit.md)中，F1 一次四着色 pass 已够用且快于四个错位 F2 patch pass。但若一个局部区域内的很多相邻顶点要**协调移动较大距离**，逐顶点操作可能把本来温和的整体变形拆成多个暂时陡峭的中间图。为把机制差异单独拿出来，构造不从 F1/F2 decoder 生成的固定网格目标。

在 \(Q=[1/4,5/16]^2\) 内取 \(W(x,y)=\sin^2(16\pi(x-1/4))\sin^2(16\pi(y-1/4))\)，在 \(Q\) 外取 0。令
\[
T(x,y)=(x,y)+A W(x,y)(1,1),\qquad A=0.006.
\]
窗口在 patch 边界的值和一阶法向导数均为 0，因而整张方形边界恒等。\(|\partial_xW|,|\partial_yW|\le16\pi\)，从而 \(u=T-\mathrm{id}\) 有 \(\|Du\|_\infty\le 2A\cdot16\pi\approx0.6032<1\)。所以解析连续图全局同胚；同一 SW–NE 三角网格的 P1 采样图逐面差商服从同一界，至少有保守下界 \(J_T\ge(1-0.6032)^2>0.157\)。实际 1025²、2,097,152 面的最小归一化面积为 0.608643。目标不是“先生成 fold 后修复”，其整个系数区间 \(|A|\le0.006\) 均有这套先验保证。

Q 的边长恰好是 1025² 网格的 64 个细单元，且 Q 的原点是 64-cell patch 划分点。F2 的**一个非重叠 64×64 patch pass**可同时更新 patch 的全部内部顶点并固定 patch 边界。完整 pass 仍遍历全域 256 个 patch，接纳 1,016,064 个活动顶点向量 latent；本目标只在其中一个 patch 提出非零运动。F1 每 pass 用四种独立顶点颜色更新，单顶点原始位移每坐标至多 \(2h=0.001953\)，因此仅由中心点 \(A=0.006\) 的总位移就得出它**至少需要 4 pass**；这不是最优所需 pass 数的定理。

## 同一百万点 GPU 的表示与 VJP 对照

两者从同一张 1025² identity P1 图开始，均采用安全比例 0.85、不设额外绝对 Jacobian floor。F2 的 teacher latent 是每个活动内点所需位移除以 patch 原始跨度 \(0.5\cdot64h=0.03125\) 后取 \(\operatorname{atanh}\)，最大绝对 logit 0.1944；一 pass 在 float32 下与解析目标采样顶点**逐元素一致**，最小 \(J_T=0.608643\)。F1 的指定 oracle 调度在 \(P\) 次 pass 后达到 \((k/P)(T-\mathrm{id})\) 的线性中间目标；对超出单步原始幅度的提议只在**构造比较用 teacher** 时把输入比率截进 tanh 定义域，F1 解码器自身不含这道事后修复。每个输出仍全脸正向。

| 机制 / teacher 调度 | 对目标顶点向量 RMSE | 最大单坐标误差 | 最小 \(J_T\) | 热启动 forward+VJP 中位秒 | 峰值 allocated GB |
|---|---:|---:|---:|---:|---:|
| F2，一个 64-cell patch pass | 0 | 0 | 0.60864 | 0.0080 | 0.442 |
| F1，1 个四着色 pass | 0.00013857 | 0.00517 | 0.27750 | — | — |
| F1，2 pass | 0.00007970 | 0.00374 | 0.21326 | — | — |
| F1，4 pass，梯度重算 | 0.00001322 | 0.00100 | 0.19037 | 0.1209 | 0.649 |
| F1，8 pass，梯度重算 | \(2.01\times10^{-7}\) | \(4.51\times10^{-5}\) | 0.60864 | 0.2419 | 0.716 |
| F1，16 pass，梯度重算 | 0 | 0 | 0.60864 | 0.4859 | 0.850 |

条件：Turing A40 GPU0、PyTorch 2.8、float32、batch1、1025² **控制顶点**；计时只含 decoder 正向与对随机全输出 cotangent 的一次 VJP，不含图像编码、query 或 loss/optimizer。每种 VJP 均有限且非零。峰值是该脚本保持目标、模块和必要输入常驻 GPU 条件下的 allocated 值，已经把非当前方案的 teacher latent 转存 CPU，避免把待比较的 31 组 F1 teacher 张量全部计入 F2 峰值。[复现脚本](../../tools/phase7_coherent_patch_motion.py)。

F2 在此**特定对齐 patch 的协调运动**里，一次就达到目标，与经16次才达到同等 float32 精度的这一 F1 oracle 调度相比 forward+VJP 约 61 倍快、峰值更小。但不能从一条线性 F1 调度推断任何 F1 latent 都至少需要16次；已证的显然幅度下界只有4次。也不能从 8 次仍有 \(2\times10^{-7}\) RMSE 推断医学/图像任务必须支付16次的成本；对应任务精度阈值要另设。F2 的 patch 边界固定是一个真实限制：若细节跨 patch 边界，需要错位 patch pass、重叠调度或更大 patch，成本会回升。[上一实验](16_dense_two_component_f1_fit.md)恰示 4 错位 F2 pass 在小幅细节上比单 F1 pass 贵。因而两条正向原语的选择应按**目标位移相对网格尺度、空间支撑和精度门槛**做 Pareto 比较，而不是一概判某条路线失败。

额外从**零 F2 latent**出发，只用全部 1025² 顶点的目标 map 平方损失作 300 步 Adam（初始学习率 0.01、余弦退火），在同一 A40 上也达到 float32 顶点 RMSE 0、最小 \(J_T=0.608643\)；训练步中位 0.00745 秒、allocated 峰值 0.467 GB。这比仅有 teacher 可表达性更强，说明此协调 patch 样本直接 latent 拟合可行。但它依然**不是图像到 latent 的训练**，且只选了一个与 patch 完全对齐的窗口；需要随机化 patch 位置、跨度和方向，才可检验泛化或学习型模块选择。
