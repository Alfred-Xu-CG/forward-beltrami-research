# 百万控制顶点训练的 CPU 流式数据：显存—速度权衡

## 对照问题

[仿射 image-to-latent 训练](45_local_affine_image_training.md)的峰值CUDA allocated约16.15GB，但它把**全部256训练目标图及128保留目标图**留在GPU。这并非正向P1层单次反传固有的显存。要检查一个可扩展的训练口径：样本在CPU按batch生成并常驻CPU，只把每一步的batch4图像、低尺度提案与目标地图搬到GPU。网络、F2粗层、两次精确P1加密、F1细层、损失及梯度**完全不变**。

新[流式生成器](../../tools/phase7_train_local_affine_residual.py)预先在CPU用同样的种子生成少量原点、向量、矩阵、纹理频率/相位/权重；每次只在GPU临时生成4例的1025²真值和512²图像，然后立即搬到CPU。hard局部仿射图像提案也分批搬回CPU。训练时从CPU取4例传回GPU；保留评价亦分批传输并按样本数/支持像素数合并RMSE。它不依赖修改安全层或重求目标。仅将已经GPU全量生成的数据事后复制到CPU**不会**降低数据准备峰值，因此本实现直接把生成过程改为batch流式。

复现一致性：相同seed、2例、batch1时，CPU参考生成与流式生成的图像、P1目标、支持掩码及频率逐张通过[本地测试](../../tests/test_phase7_affine_streaming_data.py)。相同256/128种子的线上保留集零末层基线，流式与GPU常驻版本的地图RMSE都为$3.45097656756\times10^{-6}$、image MSE都为$1.81329404200\times10^{-8}$，其他指标一致。精度差异仅在后续CPU/GPU随机采样训练轨迹中出现。

AI A6000空闲GPU2、PyTorch2.5.1+cu124、float64几何/float32图像和CNN、256训练+128保留、batch4、相同map监督与Adam学习率$10^{-4}$。CUDA allocated口径在完整数据准备前重置一次并记录准备峰值；又在基线评价后重置，记录训练步峰值，避免把两个阶段混淆。GPU reserved另未记录。

|---|---:|---:|---:|---|---|
| 全量GPU常驻，600步 | 未单列 | 16.152GB | 357.93ms | 粗/细600步均有限非零 | [先前完整训练](45_local_affine_image_training.md) |

训练阶段显存下降约54.9%，步时增加约9.8%；这只是当前AI A6000、数据布局和batch4上的实测，不保证其他PCIe拓扑/存储硬件同样权衡。即使如此，7.285GB也并非“只存百万点坐标”的理论最低内存：F2/F1各pass的autograd中间张量、图像网格采样、网络激活与输出证书均在内。CPU端则要容纳全部训练/保留目标和图像，约数GB；**GPU容量压力转成主机内存和传输压力**，不是免费消失。若真数据从磁盘按需读入，可再减少CPU常驻，但本轮尚未测试吞吐与随机I/O。

完整600步的同一128例保留集：零末层基线地图向量RMSE $3.4509766\times10^{-6}$、image MSE $1.8132940\times10^{-8}$，训练后分别为$3.4177326\times10^{-6}$、$1.7530825\times10^{-8}$；最小归一化面Jacobian由$.844913$到$.841549$，无单位图后备。对应GPU常驻的600步map训练结果是地图RMSE $3.40946\times10^{-6}$、image MSE $1.7132\times10^{-8}$。两次运行使用同一数据、损失和学习率，但流式版本的训练索引在CPU抽取，使随机优化轨迹不同；不能把最终误差差异归因于存储方式本身。实际显存节约与速度代价在100步和600步都近似稳定。

此优化表明百万控制顶点的真实训练不一定需要把数据集目标常驻GPU，却没有改变前向层的$O(V)$活跃状态下界。多GPU、更大batch及4097²带图像CNN的训练尚不能从本数表推断可行；此前4097²只在[教师latent VJP](24_global_smooth_isotopy_teacher_test.md)证明过层本身可运行。
