# 4097²四视图完整训练的激活重计算：约12%省显存、约12%增时

## 需要保存什么、重算什么

四视图模型的输出是4097²=16,785,409个控制顶点、33,554,432个原三角面上的单张P1地图。网络在2049²、4097²两个细层分别用当前地图与512²固定/移动图像重新形成局部2×2光度提示，然后进行安全四着色顶点更新。直接自动微分在前向保留这些大张量；非重入 activation checkpoint只保留细层输入，反向时**按同一公式重算**该层的提示与安全更新，再链式传梯度。它不近似求解线性系统、不减少控制网格、不改变P1几何定义；节省的是部分暂存激活，代价是额外算力。其边界仅在2049²、4097²两个反馈模块，不会自动消除全部编码器、查询、最终面证书的成本。[脚本开关](../../tools/phase7_feedback_scale_probe.py)为`--checkpoint-extra`。

同一AI主机两块启动前空闲的同型号RTX A6000 GPU2/7、PyTorch2.5.1+cu124、float32、batch1、四幅独立合成纹理、完整编码器/四项增益VJP。首先同一个未见样本seed20270317做5次CUDA同步热态完整forward+image-MSE VJP中位；随后同一32训练例seed55101、同一初始权重与Adam随机序列，各运行20步全参数image-only训练，检查输出/参数轨迹。指标时间包括编码器、4097²地图、512²图像查询、最终保守面证书与反向；allocated峰值从CUDA统计，不是reserved。20步只用于计算成本与轨迹一致性，不作为新模型有效性研究。

| 策略 | 单例完整forward+VJP热态中位 | 单例VJP allocated峰值 | 20步训练中位步时 | 20步训练allocated峰值 |
|---|---:|---:|---:|---:|
| 直接保存细层激活 | **.7561s** | 15.445GB | **.7608s** | 15.934GB |
| 2049²/4097²细层重计算 | .8467s | **13.504GB** | .8520s | **13.992GB** |

在这个实现/任务上，VJP峰值约降12.6%，训练峰值约降12.2%，时间相应约增12.0%/12.0%。两种单例前向输出的map RMSE、image MSE、最小 \(J\) 在报告精度下完全相同，均通过原面证书，编码器、粗/细增益梯度均有限。20步两条训练轨迹的最终两个细增益差最大 \(7.45\times10^{-9}\)，粗增益逐项相同，所有编码器张量的最大绝对参数差 \(4.80\times10^{-8}\)；属于本次不同GPU/重计算顺序的浮点末位差，不应夸为任意输入的严格VJP等式。20步检查点：[直接](checkpoints/phase7_full_encoder4097_C4_direct20.pt)、[重算](checkpoints/phase7_full_encoder4097_C4_checkpoint20.pt)。

此方案**没有**把4097²完整反传压到常见8–12GB设备：batch1仍需约14GB allocated，且显存口径包含训练数据常驻的实现选择。CPU offload、流式分块VJP、局部算子融合或更细粒度重算可能继续降峰值，但都要在同一地图误差、证书接受率和真实训练步上测量；不能仅凭符号上的 \(O(V)\) 工作量推断低显存。
