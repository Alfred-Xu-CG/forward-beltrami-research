# Route C：真实控制网格从 257² 到 1025² 的扩展

## 问题和严格区分的尺度

要验证的不是在固定稀疏控制网格上查询更多像素，而是直接在更密的原三角剖分上生成 P1 顶点映射并反传。令边长顶点数为 $N$，控制顶点数 $N^2$，原三角形数 $2(N-1)^2$。本实验取 $N=513,1025$；输入图像、最终 warp 查询始终为 $512^2$，光度系数估计网格始终为 $128^2$。每个控制网格重新构造 18 个边模态与各自的解析响应，并在该网格上求正 conductance 的完整平衡映射；绝不是将 257² 输出插值到 1025² 充数。

层的方程、18 模态已知频率先验、18×18 光度正规方程和隐式 VJP 在[17 节](17_photometric_conductance_layer.md)定义。所有尺度载入**仅在 257²、32 张 high32 合成训练图像上训练 300 步**的同一 18 增益检查点，且不再训练。这项实验是零额外训练的分辨率迁移与计算扩展测试，不是 1025² 训练收敛试验，更不是任意 Beltrami 输入。

## 共同设置与指标

设备为 ai 主机空闲的物理 GPU 2，float32 图像/采样、float64 边导纳/图 Laplacian/PCG，batch 1。数据为固定种子 99317 的相同 8 个 high32 合成图像—形变对。计时热身后重复 3 次，取中位数；forward 包含图像到 18 维 latent、全控制网格 PCG、512² 查询、图像 warp 和 MSE loss，VJP 包含该 loss 对 fixed 图像、moving 图像和 18 增益的梯度。峰值为 PyTorch CUDA allocated，不包括 CUDA 驱动缓存、其他进程或数据准备期的主机内存。预计算的时间和峰值显存另计，它一次建立同规模的 18 响应，可被所有输入复用。

每例图像误差是 $512^{-2}\sum_p (I_m(Y(p))-I_f(p))^2$，query-map RMSE 是 $\sqrt{(2Q)^{-1}\sum_p\|Y(p)-Y^*(p)\|^2}$，其中 $Q=512^2$、$Y^*$ 是只供事后评价的合成真映射。face Beltrami RMSE 用全部原三角形的 P1 Jacobian $J$ 计算 $\mu(J)=(J_{11}-J_{22}+i(J_{21}+J_{12}))/(J_{11}+J_{22}+i(J_{21}-J_{12}))$，再与真映射在相同面重心的 Jacobian 所给 $\mu^*$ 比较：$\sqrt{F^{-1}\sum_f|\mu_f-\mu_f^*|^2}$。最小行列式、最大 $|\mu|$ 均遍历 8 例的全部原面。频率 32 振幅率是以控制顶点上 $\sin(64\pi x)\sin(64\pi y)$ 对两坐标位移投影所得的标量，与真系数做过原点最小二乘斜率；不是局部几何误差。前向/伴随真实相对残差用 $\|b-Ax\|_2/\max(\|b\|_2,\epsilon)$，不是内部递推 residual。

## 拓扑解释与剩余空白

每条边权严格处于 $(1,16)$，边界固定为单位正方形；[19 节](19_square_boundary_tutte_theorem.md)证明这一具体共线边界网格满足适用的精确 P1 同胚条件。PCG 的浮点输出不能直接套精确平衡定理，故求解器每次在**所有原面**检查严格正有向面积，并计算真实残差。对固定正向边界的 PL 盘映射，这提供数值输出自身的全局无折叠证书；表中的最小 $\det J$ 是实际数值余量。它与只在 512² 查询点检查正 Jacobian 不同。

扩网格使面 $\mu$ RMSE 略降、image/map 误差几乎不变，说明当前测试的主要误差来自受限 18 模态及图像到 latent 的估计，而非 257² 几何离散。1025² 每步约 0.36 s forward+VJP，训练若需大量迭代仍昂贵；一次性 7.46 GB 响应预计算在中等 GPU 上也是实质瓶颈，尽管每步峰值低于 1 GB。A8 的 1025² 单例无再训练测得约 65.9/155.8 ms、峰值 3.36 GB；两个脚本的输入常驻、精度和 map 机制不同，不能据此断言 C 整体优于或劣于 A。没有进行 1025² 的多步 image-to-latent 重新训练，也没有摄影域外在该尺度的测量，不能把这项分辨率迁移写成百万点训练/泛化已经解决。

复现入口为 tools/phase6_scale_photometric_layer.py，原始逐例记录为 raw_results/c_photometric_control513_gpu2.json 和 raw_results/c_photometric_control1025_gpu2.json；1025² 首个单例为 raw_results/c_photometric_control1025_one_gpu2.json。脚本的 --side 参数是真控制顶点边长，不是查询图像边长。
